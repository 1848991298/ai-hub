# 分支与工作区盘点

对当前项目做一次可复核的只读快照，先回答数量，再说明改动内容和处理顺序。调用方式：`$git-worktree-audit`，可附项目路径。

## 采集

先确认实际仓库根目录、Git common dir 和 remote 归属，按当前项目规则确定范围。同一 common dir 下的 worktree 共用分支和 stash；独立 clone、同名目录、GitLab/GitHub 的不同仓库不能混算。

运行本 skill 的采集脚本，脚本只用 Python 标准库和本机 Git：

```sh
python3 <本 skill 目录>/scripts/audit.py --repo <项目目录> --output <仓库外的临时 JSON 路径>
```

不传 `--output` 时向标准输出写完整 JSON；传入后仅在终端显示摘要。把输出放到仓库外，避免报告自身被计入未跟踪文件。读取 JSON 时先取汇总与逐工作区统计，按需要读取文件清单，不把大批日志路径一次灌进上下文。

- 不自动 fetch、pull、checkout、建分支、stash、unshelve、暂存、commit、push、prune、解锁或删除目录，也不改 Git 配置。上游领先/落后来自本机跟踪引用，注明扫描时间和“未联网刷新”；需联网核对时遵循用户当次范围。
- 分别统计：登记 worktree、实际可读取 worktree、缺失/不可读取/裸仓库、detached HEAD、本地分支、远端跟踪分支、存在未提交改动的工作区。不要把一个分支等同一个目录，也不要把 `origin/HEAD` 计成独立分支。
- 已暂存、未暂存、未跟踪、未合并分别列明；同一个文件可同时有暂存及未暂存修改，这两项不可直接相加当作文件总数。重命名列出原路径和新路径。
- stash 按 common dir 只计一次。Shelf 扫描每个 worktree 的 `.idea/shelf`，列明补丁、文件清单及元数据状态；无 XML 的补丁标为“残留补丁，IDE 可见性待核实”，不能说它已恢复或一定能在 Shelf 页找到。自定义 Shelf 位置或子项目另开 IDE 时，按其配置补查并注明覆盖范围。
- 缺失目录、无权限、仓库关联异常、Git 读取失败或扫描时 HEAD 变化都单列，不能归为“干净”。保留可能仍有恢复价值的登记和文件。

## 分析与建议

采集脚本的路径分类只是线索。对含业务源码的工作区，先看实际 `git diff --no-ext-diff --no-textconv`、`git diff --cached --no-ext-diff --no-textconv` 和必要的未跟踪源码，再归纳修改目的；未阅读的部分明确标为待审查，不能仅凭分支名、文件名、改动数量或已有暂存就认定可以提交。避免输出凭据、token、用户原始健康数据或完整设备日志。

给每处改动一个有依据的建议：

- **可整理为提交候选**：已读差异，业务范围清楚，实现与必要测试能成组；标明已运行的检查及缺失验证。这是建议，不是提交授权。
- **待验证 / 继续开发**：实现不完整、混有多项任务、冲突、验证不足或与现行基准关系未查清；说明具体缺口。
- **仅本地保留 / 不纳入业务提交**：日志、安装包、构建产物、验证快照、Shelf、恢复备份及敏感配置；保留原件，不能以“不建议提交”为由自动清理。确需交付的证据或构建文件按项目约定单独审查。
- **已提交但待处理同步**：上游有效且 ahead > 0；单列已有提交，不与未提交文件混为一谈。无上游或上游已消失时标为“推送状态未知”，不推断成未推送。

同一问题出现在多个 worktree 时，用实际 diff / 提交核对重复与差异，避免建议重复提交。历史分支的大批改动也可能只是迁移、基准不同或恢复现场，未经检查不要整批合并。遵循项目的主线、市场分支隔离及当次“不操作 master”等约束；这项盘点不改变开发基准或现有分支。

## 交付

先给总数及优先处理项，再给完整可查清单：

1. 每个 worktree 的绝对路径、实际分支或 detached HEAD、可读取状态、已暂存/未暂存/未跟踪/冲突数量、上游和领先/落后。
2. 每个有改动工作区的业务摘要、完整文件列表、建议和验证边界；日志或快照较多时按目录汇总数量，并在可打开的报告中保留全量路径，不能只用几个例子替代完整清单。
3. 没有检出到目录的本地分支、远端跟踪分支列表、stash 和 Shelf 清单；说明共享储存与工作区改动的区别。
4. 不建议纳入业务提交的范围、缺失登记及可疑重复项；说明本次实际没有执行哪些 Git 写操作。

清单大时生成可检索的本地报告，正文保留关键数字和建议；不要将项目私有状态上传到公开网站。检查前后保持被审计仓库的 HEAD、分支、索引和本地改动不变，差异若来自其他并行任务要如实说明。

只有用户进一步要求执行提交时才进入 `$commit-by-business`，展示完整文件、message、仓库/分支及合入、推送范围，并按当前规则等实际确认。本 skill 本身不把“建议提交”变成提交动作。
